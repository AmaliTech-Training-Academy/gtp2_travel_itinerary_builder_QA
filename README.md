🧪 Travel Itinerary Builder – Quality Assurance Project
📌 Project Overview

This repository contains the Quality Assurance (QA) work carried out for the Travel Itinerary Builder application. The project focuses on ensuring the reliability, functionality, and quality of the application through structured manual testing and API testing practices.

The QA activities were performed as part of a collaborative development effort, closely working with developers in a distributed team environment to validate requirements and improve overall product stability before release.

🎯 Objectives

  • Validate application functionality against business and technical requirements

  • Identify and document defects early in the development lifecycle

  • Ensure stable releases through regression and user acceptance testing

  • Verify backend functionality via REST API testing

  • Strengthen collaboration between QA and development teams

🧩 Scope of Testing

The following testing types were conducted:

  • Functional Testing

  • Regression Testing

  • User Acceptance Testing (UAT)

  • API Testing (REST APIs)

  • Integration Testing

  • Exploratory Testing

🛠 Tools & Technologies

  • Manual Testing: Test case design, execution, and reporting

  • API Testing: Postman

  • Test Management & Defect Tracking: Jira / Xray

  • Documentation: Excel / Markdown

  • Collaboration: GitHub, Agile ceremonies (stand-ups, reviews)

🧪 Testing Activities Performed
🔹 Manual Testing

Designed detailed test cases covering core user flows such as:

- User authentication

- Itinerary creation and modification

- Data validation and error handling

- Executed regression tests to ensure new changes did not impact existing functionality

- Performed UAT to validate business requirements before release

- Documented test results clearly and consistently

🔹 API Testing

- Tested RESTful APIs using Postman

Validated:

- HTTP status codes

- Request and response payloads

- Error handling and edge cases

- Verified backend behaviour independently of the UI

- Supported early detection of integration issues

🐞 Defect Management

  • Logged and tracked defects with clear reproduction steps

  • Included severity, priority, and expected vs actual results

  • Collaborated closely with developers to retest and verify fixes

  • Ensured defects were resolved before release sign-off

🤝 Team Collaboration

  • Worked as part of a distributed Agile team

  • Participated in:

  • Daily stand-ups

  • Test planning and review sessions

  • Maintained clear communication with developers and stakeholders

  • Ensured QA feedback was actionable and timely

📈 Outcomes & Value Delivered

  • Improved application stability before production release

  • Early identification of functional and integration issues

  • Better alignment between requirements and delivered features

  • Strengthened QA–development collaboration

  • Increased confidence in release quality
